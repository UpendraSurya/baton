## 1. TL;DR

- **Added `baton.swarm`**, a routing memory for handoffs, keyed by the pair
  (from agent, to agent). It works like ant-colony pheromone:
  - ratified runs reinforce the handoffs that delivered;
  - failed runs and abandoned detours weaken the handoffs they took;
  - every run fades every trail a little (evaporation);
  - an exploration floor keeps every allowed agent reachable.
- **Advisory only.** It never changes `can_hand_to`. All ten kernel stop rules
  and guards are untouched.
- **Added `bench/swarm_sim.py`**, a paired benchmark: 7 arms, 5 scenarios,
  52,500 runs through the real runtime, $0, deterministic, with an oracle gate.
- **Headline result (simulation only):** when the model's guess of the right
  desk is wrong in a consistent way, or the right desk changes mid-stream, the
  swarm arm beats blind dynamic routing by **6–15 points (p < 0.001)**; the
  reputation arm does not. On a single ticket type, the fixed graph (static)
  is still best.
- **Not proven:** whether a *model* that reads the trail notes routes better.
  That needs paid tier-2 runs, and none have been done.
- **Two bugs in the first version of `baton.swarm` were found and fixed:**
  1. A relative exploration floor meant evaporation never changed any
     probability.
  2. Misroutes inside eventually-ratified runs were credited as deliveries.

## 3. `baton.swarm` — design

### 3.1 The model

A **trail** belongs to one directed edge `(src, dst)`, meaning "agent `src` handed
the baton to agent `dst`". For each observed run, in chronological order:

```
every trail:                                trail <- (1 - evaporation) * trail
ratified run, edges on its loop-free route: trail += deposit / hops
every other edge the run took:              trail <- (1 - penalty) * trail
```

Choosing the next agent uses the Ant System transition rule over the **legal
candidates only**:

```
p(dst) ∝ max(trail, explore * deposit) ** alpha  *  heuristic(dst) ** beta
```

### 3.2 Defaults

| constant | value | meaning |
|---|---|---|
| `DEFAULT_EVAPORATION` | 0.1 | share of every trail lost per observed run |
| `DEFAULT_DEPOSIT` | 1.0 | reinforcement one ratified run adds, split across its hops |
| `DEFAULT_PENALTY` | 0.3 | extra erosion on edges of failed runs or abandoned detours |
| `DEFAULT_EXPLORE` | 0.05 | absolute floor (× deposit), the MMAS tau_min |
| `DEFAULT_MIN_RUNS` | 3 | `note()` stays silent about an edge with less history than this |
| `DEFAULT_NOTE_LIMIT` | 4 | maximum edges named in one note |

### 3.3 Public API

```python
from baton import swarm

c = swarm.Colony(evaporation=0.1, deposit=1.0, penalty=0.3, min_runs=3)
c.observe(records)            # one run's Trace.records(); False if it has no run_end
c.observe_result(run_result)  # the same, read from RunResult.trace
c.trail("intake", "docs")     # Trail(src, dst, strength, runs, ratified) or None
c.trails(src=None)            # strongest first, in a stable order
c.weights(src, candidates, alpha=1, beta=0, heuristic=None, explore=0.05)  # probabilities summing to 1
c.choose(src, candidates, rng)          # sample; rng required, so runs are reproducible
c.note(src, candidates)                 # prompt line with counts only, or ""
c.annotate(agents)                      # copy of agents, note appended to instructions
c.to_dict() / swarm.Colony.from_dict(d) # JSON-safe persistence
swarm.from_traces(traces, **kw)         # build a Colony from past runs, oldest first
swarm.from_reputation(rep, unknown=0.5) # ACO heuristic = 1 - rework rate; `unknown` has no default
swarm.edges_of(records)                 # (edges, terminal_reason | None, hops)
swarm.loop_free(edges)                  # the route that delivered, detours removed
```

### 3.4 Rules the module keeps, matching baton's existing style

- **Advisory only.** `annotate()` changes `instructions`, never `can_hand_to`.
  `weights()` returns probabilities over exactly the candidates passed in; a
  trail to a non-candidate is ignored.
- **Counts travel with the signal.** `Trail.runs` and `Trail.ratified` never
  decay. `note()` states "handing to X ratified in k of n past runs".
- **An unfinished run is not a failure.** A trace with no `run_end` is skipped
  (`Colony.skipped += 1`).
- **No invented numbers.** `from_reputation(unknown=...)` is required, the same
  rule as `crossover(perception_accuracy=...)`.
- **Which moves count as edges:** only routing decisions the runtime accepted.
  HANDOFF goes to `to`; REJECT goes to `to`; PROPOSE_DONE goes to the gate
  named in `run_start.charter`. Moves the runtime made itself (escalations,
  forced gate calls) lay no trail.
- **Trails are bounded:** a trail can never exceed `deposit / evaporation`.
- **No unbounded growth:** trails below 1e-9 are pruned.

### 3.5 Loop-free credit (ant-routing loop elimination)

Walk the agents in visit order. Whenever an agent reappears, cut the cycle
since its last visit. Two examples:

- misroute: `intake, docs, gate, intake, engineering, gate` → `intake, engineering, gate`
  (the handoff to docs is not credited, and it is penalised)
- rework: `intake, engineering, gate, engineering, gate` → `intake, engineering, gate`
  (the correct handoff keeps its credit)

A gap in the record, where the runtime moved the baton, is never bridged into
an edge that no agent actually took. `Trail.ratified` counts only runs the edge
*delivered* by.

## 4. Bugs found during this work (all fixed, all covered by tests)

1. **Relative exploration floor made evaporation pointless.** Version 1 floored
   candidates at `explore × strongest trail`. Scaling every trail by the same
   factor then leaves the weights unchanged, so evaporation never moved a
   probability. In one seeded run the colony still had not found the new route
   after 40 runs.
   - Fix: absolute floor `explore × deposit`, plus failure `penalty`.
   - Median runs to recover after the route changed, across 20 seeds:

     | setting | median | max |
     |---|---|---|
     | penalty 0 | 22.5 | 38 |
     | penalty 0.3 | 8 | 23 |

   - Test: `test_evaporation_alone_moves_the_odds`.
2. **Misroutes credited as deliveries.** In an eventually-ratified run, every
   edge was rewarded, including the wrong handoff that the gate sent back.
   - Fix: `loop_free()`.
   - Tests: `test_a_misroute_in_a_ratified_run_is_not_credited`,
     `test_rework_keeps_credit_on_the_right_handoff`,
     `test_loop_free_never_bridges_a_gap`.
   - **Side effect, recorded and not explained yet:** the swarm arm dropped
     from 84.5% to 80.8% on the `misled` scenario, while `homogeneous`,
     `mixed`, `systematic` and `drift` improved. The fix was kept because the
     old rule made `note()` state something false.
3. **Benchmark harness bug** (in `bench/swarm_sim.py`, never in the library).
   The oracle router was given the ticket class ("billing") instead of the desk
   name, which made the oracle score below blind dynamic. Fixed before any
   reported numbers.

## 5. Benchmark — `bench/swarm_sim.py`

### 5.1 World

- Tickets have a hidden class: billing, bug or howto.
- Each class is resolved by exactly one desk: billing→refunds, bug→engineering,
  howto→docs. A fourth desk, payments, only matters in the drift scenario.
- The right desk does acceptable work 85% of the time (`QUALITY`).
- Intake does not see the class. It sees a *perceived label* drawn from a
  per-scenario confusion matrix, plus a prior mapping from label to desk (what
  a model would get from the personas).
- The gate is an oracle:
  - it ratifies only good work from the right desk;
  - it sends wrong-desk work back to intake to be re-routed, if the arm's
    whitelist allows it;
  - it sends weak work back to the desk that produced it.
- Every dispatch costs $0.001. `max_hops` is 6, so a run survives one misroute
  but not two. That keeps the arms off the ceiling (the "window problem" in
  `docs/measuring-dynamic-routing.md`).
- Pairing: each ticket's class, label and work-quality draws are seeded by
  `(seed, i)` and are identical in every arm.
- Statistics: exact two-sided McNemar test on per-ticket outcomes.
- The wall-clock guard is off, because it spawns a thread per dispatch; every
  other guard is on.

### 5.2 Arms (they differ only in how intake picks a desk)

| arm | policy |
|---|---|
| static | fixed DAG: intake → the desk for the most common ticket class → gate |
| oracle | knows the right desk; this is the ceiling, not a contender |
| dynamic | prior desk for the perceived label; re-routes uniformly at random among untried desks |
| reputation | as dynamic, but re-routes to the desk with the lowest rework rate (`reputation.from_traces`, rebuilt every 10 runs) |
| swarm | one `Colony` per perceived label; ACO rule with heuristic 1 for the prior desk and 0.2 for the others (beta=1); re-routes by the same rule |
| swarm-flat | one `Colony` for all labels (no per-label trails) |
| swarm-cold | per-label colonies with no prior (beta=0) |

### 5.3 Scenarios

| scenario | description |
|---|---|
| homogeneous | every ticket is billing; perception 85% |
| mixed | 3 classes, equal shares; perception 70%, errors uniform |
| systematic | bugs read as howto 60% of the time; the prior desk is still the likeliest right one for every label |
| misled | mix 20/50/30; 70% of bugs read as howto, so for the "howto" label the prior desk (docs) is usually wrong |
| drift | mixed at 85% perception; halfway through, billing moves from refunds to payments and the prior is not updated |

### 5.4 Results (300 tickets × 5 seeds, default settings)

Share of tickets delivered. The drift row is the second half only, after the
change.

| scenario | static | dynamic | reputation | **swarm** | swarm-flat | swarm-cold | oracle |
|---|---|---|---|---|---|---|---|
| homogeneous | **99.6%** | 89.1% | 85.2% | 98.2% | 99.1% | 97.5% | 99.6% |
| mixed | 34.3% | 77.2% | 79.6% | 79.1% | 72.2% | 74.1% | 99.6% |
| systematic | 34.3% | 78.7% | 79.9% | **84.9%** | 71.3% | 77.5% | 99.6% |
| misled | 47.8% | 68.5% | 69.7% | **80.8%** | 71.4% | 77.5% | 99.6% |
| drift (2nd half) | 32.1% | 66.8% | 58.4% | **82.1%** | 65.3% | 83.5% | 99.5% |

Swarm vs dynamic, McNemar (`+a/−b`: tickets only swarm delivered / only
dynamic delivered):

| scenario | result | p |
|---|---|---|
| homogeneous | +144/−8 | <0.001 |
| mixed | +112/−83 | 0.045 |
| systematic | +164/−71 | <0.001 |
| misled | +282/−97 | <0.001 |
| drift | +171/−56 | <0.001 |

Swarm vs static on homogeneous: +0/−21, so static wins there.

Cost per delivered ticket in drift: static $0.0167, dynamic $0.0056,
reputation $0.0059, **swarm $0.0048**, oracle $0.0033.

### 5.5 Sensitivity to the prior weight (`--prior`, the weight given to non-prior desks)

| prior weight | homogeneous | mixed | systematic | misled | drift |
|---|---|---|---|---|---|
| **0.2 (default)** | 98.2% | 79.1% | 84.9% | 80.8% | 85.7% |
| 0.5 | 97.4% | 76.5% | 82.3% | 80.5% | 85.2% |
| 0.8 | 98.0% | 76.3% | 81.6% | 76.2% | 84.1% |

(The drift column here is the full run, not the second half.)

### 5.6 Findings

1. **One ticket type: keep the fixed graph.** Routing is overhead there,
   consistent with `baton.crossover`.
2. **Honest random noise: learning barely helps.** Swarm, reputation and
   dynamic end up within 2.5 points of each other.
3. **Consistently wrong guesses or drift: the per-label trail is the only
   learned arm that wins everywhere.** Reputation drops *below* blind dynamic
   under drift, because it scores agents, not handoffs.
4. **The gain comes from re-routing, not the first pick.** Swarm's first-pick
   accuracy is at or below dynamic's, because sampling is exploration. The win
   is re-routing to the desk the trail says delivers.
5. **Per-label trails matter.** swarm-flat underperforms blind dynamic in 3 of
   5 scenarios.
6. **The prior limits how fast evidence wins.** In `misled` the colony learned
   the right answer (intake→engineering: strength 0.43, 70/103 ratified;
   intake→docs: 0.02, 70/161), but the 5:1 prior held the first pick at
   roughly 55/45.

### 5.7 What this does NOT show

- Whether a real LLM reading `annotate()` notes routes better. This needs a
  tier-2, paid run; the corpus issues in `docs/measuring-dynamic-routing.md`
  still apply.
- Behaviour when desk quality depends on the individual ticket, not just the
  class.
- Behaviour with a gate that sometimes ratifies wrongly. That would lay trail
  on bad routes, and nothing here measures how fast it would mislead the
  colony.
